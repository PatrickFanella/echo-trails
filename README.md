# EchoTrails

Public place-stories for real-world locations.

Core promise: people leave short Echoes tied to real-world Places so others can discover the stories of those Places.

## Status

Early product/technical planning plus generated iOS prototype reference.

Current codebase:

- native SwiftUI iOS prototype generated by Rork, retained as reference-only
- Go API profile endpoints under `apps/api`
- Go API location proof validation primitives under `apps/api`
- Go API server primitives and auth boundary packages under `apps/api`
- monorepo skeleton under `apps/`, `packages/`, and `infra/`
- product/technical planning docs
- Open Pilot-ready issue and PR templates

Planned beta:

- iOS TestFlight app
- custom Go REST API
- Postgres/PostGIS
- Redis jobs
- S3-compatible media storage/CDN
- React/Vite admin web
- minimal public preview web

## Quick start

```bash
make verify
```

Linux verification currently checks repo structure, docs, Open Pilot templates, committed secret filenames, scaffold-aware Go, TypeScript, OpenAPI, and Swift gates, Go migration unit tests, and embedded PGlite/PostGIS up/down SQL execution. Missing implementation scaffolds are skipped with explicit messages; Swift/Xcode checks run only on macOS. With `apps/api` present, verification runs Go fmt/vet/tests for the API. The live Postgres/PostGIS migrate-up integration test also runs when `ECHOTRAILS_TEST_DATABASE_URL` and `psql` are available.

## API domain primitives

`apps/api/internal/locationproof` validates the scoped creation-token preflight for Echo creation: fresh proof, GPS accuracy threshold, selected Place radius/boundary, restricted Place rejection, ambiguous eligible Place rejection, trust/rate gate decisions, and opaque creation token issuance without exact private coordinates in the token string.

## Auth configuration

Sign in with Apple production verification must be configured with these secret names only:

- `ECHOTRAILS_APPLE_TEAM_ID`
- `ECHOTRAILS_APPLE_CLIENT_ID`
- `ECHOTRAILS_APPLE_KEY_ID`
- `ECHOTRAILS_APPLE_PRIVATE_KEY`

Do not commit secret values or signing material.

## API

The Go API lives under `apps/api` and currently exposes passwordless email auth, session, and scoped profile endpoints:

- `POST /auth/email/start`
- `POST /auth/email/verify`
- `POST /sessions/refresh`
- `POST /sessions/logout`
- `GET /me`
- `PATCH /me`
- `GET /users/{handle}`

Local development can run the API with `ECHOTRAILS_AUTH_EMAIL_DEV=1`; that opt-in dev adapter prints email codes for manual testing and must not be used in production.

The `/me` endpoints use the current auth boundary placeholder headers from local tests (`X-EchoTrails-User-ID`, `X-EchoTrails-User-Email`) until the session middleware lands. Public profile responses are pseudonymous and omit private account fields.
